# 评测说明

技术部分最高60分。展示、容器化与人气评分合计40分，按组委会另行发布的细则评价。网站只展示技术综合分及资格状态，不公开技术子项分值与权重。

## 评价内容

- 预测：需求电量、连接停留时长、下一步到达数。
- 世界模型：自然充电的负荷、能量、活跃车辆预测。
- 干预：容量EDF干预轨迹，以及相对自然充电的响应差。
- 决策：完成率、交付、同服务条件下的峰值与成本改善。
- 解释：方法、假设、限制字段；结构检查不能代替人工质量审查。

误差项目相对固定历史参考模型评价。参考误差近零表示没有可测改善空间，不凭相同零误差获得改善分。所有队伍在相同固定基线执行状态预测，不能靠改变策略使预测任务变容易。

## 资格与物理门槛

每场景必须物理合法；未知token、NaN、形状错误、违规功率等拒绝。逐场景完成比例门槛：Caltech至少0.85、JPL至少0.65、Office至少0.85。任一场景不达标即 DQ（不进入合格技术榜），不以均值掩盖。参考模型不保证通过所有场景，尤其Office。

开发集24个episode，冻结最终测试集24个episode。开发反馈和榜单不等于正式排名。最终测试标签不通过网站下载或即时反馈。

## 干预与行动环境

干预响应须同时优于无效应和固定中位数参考，轨迹技能受到效应技能限制。复制natural作为干预预测、把效应压成零，不会获得干预改善分。参考误差接近零时不产生改善分；仅效应无改善不单独导致 DQ。

act的行动限额为capacity_kw与forecast_capacity。intervention_capacity是公开反事实容量，不是行动容量；它不包含未来车辆或真实需求标签。natural与capacity_edf必须从同一状态开始，只改变反事实容量，不改变需求、到达、离开或已交付量。该效应是模型内物理效应，不是现实用户价格行为的因果证据。

训练标签必须在规定截日前完成；不得使用隐藏标签、未来到达或记忆测试场景。任何模型架构均可，架构名称不直接加分。

最后请求值是参考快照，不一定在车辆到达时填写。相关接口细节见INTERFACE.md。



### 完成率判定容差

评分时逐车判断：在该场景可服务时段内，剩余未交付电量不超过该车场景目标电量的3%，即计为完成。完成率是满足此条件的车辆数除以场景车辆总数，不是全站送达电量占比。3%按每辆车自身的目标电量计算，不能用其他车辆的超额交付抵消。Caltech85%、JPL65%、Office85%的逐场景门槛以及物理功率约束保持不变。仅改变评分的完成判定，不改变模拟器充电过程或charging_complete观测。
