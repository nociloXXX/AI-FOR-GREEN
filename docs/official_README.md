## 从预测到世界模型与决策

### 1. 这里的世界模型是什么

只预测一辆车需要多少电、会停多久，还不能回答整个站点接下来会怎样。比赛中的世界模型要从当前状态出发，推演未来一段时间的充电过程：哪些车还在充电、它们还需要多少电、功率如何分配、站点负荷怎样变化。

模型可以学习需求、停留和到达规律，也可以结合已知物理关系计算后续状态。例如，在一个时间步内，交付电量取决于充电功率和时间长度，并受到剩余需求、充电桩功率和站点容量限制。模型输出的预测要与这些关系一致。这里不要求特定神经网络架构。

### 2. 为什么说“因果”和“反事实”

这里关注的不只是“通常会发生什么”，还包括“改变充电条件后，会发生什么”。反事实预测从同一个当前状态出发，比较两种指定条件：

- `natural`：不施加站点总容量限制，当前需要充电的车辆按充电桩功率上限充电，直到完成或离开。
- `capacity_edf`：按公开的 `intervention_capacity` 总容量序列扣除背景负荷后分配可用充电功率，并按预测离开较早的车辆优先充电。

两种预测使用相同的需求、到达、离开假设和已交付电量，只改变指定的容量条件与充电策略。比较两条轨迹，才能看出限流造成的负荷变化及后续回补，而不是把两组不同车辆的结果当作干预效应。

比赛中的因果含义是模拟环境内明确改变条件所产生的物理响应，不代表已经证明真实用户会因价格或其他措施改变行为。未来车辆的真实到达、需求和离开标签不会提供给模型，需要用公开历史数据估计。

### 3. 各个接口分别做什么

这些是模型的方法接口，不是网络端口。提交的 `build_model(training)` 返回一个提供以下方法的模型对象：

- `predict(features)`：接收一辆已出现车辆的公开特征，输出预测需求电量 `demand_kwh` 和连接停留时长 `dwell_hours`。停留时长以小时为单位，不是离开的钟表时间。最后请求值只是申报快照，不能当作真实需求或已知的到达时意图。
- `arrival_rate(site, hour, weekday)`：估计指定站点和时段内，每15分钟会到达多少辆车。输出非负的期望数量，可以是小数，不是某辆车的到达概率。
- `act(observation)`：根据当前观测决定实际分配功率，返回 `{车辆token: 请求功率kW}`。只可操作当前连接的车辆，遵守充电桩和站点容量限制。实际行动使用 `capacity_kw` 与 `forecast_capacity`，不能拿反事实容量代替行动限额。
- `forecast(observation, horizon_steps, intervention)`：从当前状态预测指定步数内的充电负荷 `ev_load_kw` 和活跃车辆数 `active_count`。每步15分钟；返回两个长度等于 `horizon_steps` 的非负有限数值序列。分别对 `natural` 和 `capacity_edf` 条件给出预测。活跃车辆指已到达、未离开且仍有充电需求的车辆，不等于所有还插着枪的车辆。
- `explain()`：说明模型怎样得到预测、怎样做决策，以及哪些条件下可能失效。它返回结构化说明，不负责产生充电动作，也不替代预测结果。

### 4. explain() 要写什么，如何评价

返回一个字典，包含 `method`、`assumptions`、`limitations`：

```python
{
    "method": "说明训练方法、状态推演方式与功率分配策略",
    "assumptions": ["列出模型依赖的假设及适用条件"],
    "limitations": ["列出信息缺失、误差来源和可能失效的情况"]
}
```

自动评测检查字典中是否有非空的 `method`，以及非空的 `assumptions`、`limitations`。这是结构和内容存在性检查，不会自动核实说明是否真实、论证是否充分，也不会因为使用某个架构名称就认可效果。参赛者应填写与实际代码一致的说明；作品展示中的解释质量仍需人工审查。

## 原理

模型在车辆到达时预测需求/停留时长，用历史训练数据学习到达率；基于当前观测预测未来3小时负荷/活跃车数及两个固定策略的反事实响应；策略只看已到达车辆和本模型预测。

你能看到：到达时本地时刻、星期、站点、固定6.6kW充电桩额定限制、当前连接token、已交付电量、是否充电完成、历史到达计数、已知电价/背景/容量。你看不到：未来到达车辆、真实目标需求、真实离开时间、原session_id/用户ID/曲线文件、裁判state.remaining。charging_complete是执行后的真实观测，不是提前告知未来需求。

需求训练标签为历史已交付电量，不称真实用户意图；测试世界按同样历史已交付电量建模，E额外合成乘以1.35，实际窗口和额定功率裁剪。离开标签是实际episode内停留时长。固定6.6kW避免从测试曲线的未来峰值反推“已知”能力。

## 干预评分：须优于无效应与中位数两种基线

同一固定状态下，真实响应差为 capacity_edf 与 natural 的负荷之差。效应误差按 MAE 计算；无效应基线误差为真实响应差绝对值的均值。效应技能 = clip(1 - 队伍效应误差 / min(无效应误差, 固定中位数模型效应误差), 0, 1)。分母接近零时技能记 0，不产生改善分。

干预响应须同时优于零效应和固定中位数参考；干预轨迹技能受效应技能限制。复制自然轨迹不能获得干预改善分。参考误差接近零时不产生改善分；仅效应无改善不单独导致 DQ。

## 公开容量冲击与行动环境分离

行动测试仍使用原有容量环境。act(observation) 的限额是 capacity_kw 与 forecast_capacity，不能把干预容量当作行动限额。字段 intervention_capacity 是从当前步起的公开反事实总站点容量序列，长度与 forecast_capacity 相同，单位kW。它不含未来车辆或真实需求标签。

forecast(observation, horizon_steps, "natural") 保持自然充电定义；"capacity_edf" 使用 intervention_capacity 减 forecast_background 后的EV容量，按最早离开优先，评估限流和后续回补。两种预测须从同一状态开始。仅改变反事实容量，不改变需求、到达、离开或已经交付的能量。字段 forecast_capacity 只用于实际行动容量。

干预环境按全信息离线可达性设计，并在全部场景验证全部目标可以完成；选手仍只能使用在线信息。该反事实是模型内物理效应，不是对真实用户价格反应的证据。可以从截日前公开需求/停留数据学习潜在状态，再结合容量和当前交付状态推演响应。不允许使用隐藏标签、未来到达或记忆场景。

# 最后请求值字段

`ArrivalFeatures.last_requested_energy_kwh: Optional[float] = None`。
训练表中的同名字段表示原始会话记录里保留下来的最后一次提交请求值，单位 kWh。缺失为 JSON `null` / pandas NaN，Office 的2019及以前训练表全部缺失（2020后会话可能非空）。只保留正有限值，不从实际交付、仿真目标或预测值填补。

## 可以假定什么

这是最终会话记录中的最后请求快照，是驾驶者申报值，不是准确交付目标。比赛若采用此字段，所有队伍在该合同下获得相同信号。历史训练表的交付标签、停留标签、原行顺序不变。

## 不能假定什么

我们没有提交时间戳，不能证明请求在车辆连接/预测时已知，不能将使用此字段的结果称为严格在线、无未来信息或到达时刻意图识别结果。名字含 last，不能改称 arrival_request。此版本的信息合同与原版本不同，分数不应当作同等信息下的直接进步。不能把申报值替换为真实需求、把缺失当零或用来还原司机身份。

未来生成车辆还没有真实会话快照，设 None。冻结场景的连接/离开数组必须与原始行顺序完全对齐，否则拒绝装载。burst（高峰）场景通过复制原车池增加同时出现的车辆数量，因此复制车辆继承原车辆同一份最后请求快照。其他人工生成ID没有可验证映射则 None。不能通过猜测ID后缀建立对应。请求仅随已经出现的车辆传输，不公开未来到达/请求表。
